What it is
Before you inject anything, map who reads it. For every writable log, file, dataset, model, branch, registry tag, config, or queue item, identify the process that consumes it, the identity it runs as, what triggers it, and where the result becomes observable. Most agent findings die because the input was accepted and never consumed. Acceptance is not execution.
Example payloads
# Map ONE writable input. Fill every field.
input:       <path | table | branch | queue>
writable by: <who>
transformed: <normalize | truncate | dedupe>
selected by: <retrieval | query | glob>
trigger:     <event | schedule | queue | load>
runs as:     <identity@host>
can reach:   <paths, network, secrets>
observable:  <where the result shows, NOT the input>
cleanup:     <remove object + clear retry state>

# Then one inert canary. Grep the far side.
# Acceptance is not consumption.

What it is
AI stacks stack proxies. A gateway, a rate limiter, an auth middleware, a model router, and a backend rarely agree on what a path means. Compare how each layer interprets virtual hosts, methods, suffixes, redirects, encoded and double-encoded paths, separators, control characters, and upgrade routes. Prove the disagreement on a harmless known resource before you test impact.
Example payloads
# Same known-good resource, through every layer.
/v1/models      /v1/models/     /v1/models;
/v1//models     /v1/./models    /v1/models%2f
%2e%2e%2f       %252e%252e%252f ..%c0%af

# Same path, different host claim
Host:   :authority:   X-Forwarded-Host:

# Auth middleware frequently skips upgrades
Connection: Upgrade   on an authenticated route

# The finding is the DISAGREEMENT, not the 200.

What it is
Probe whether a tool's scope limit is enforced in code or only in the prompt. Compare known-existing and known-missing synthetic resources, both inside and outside the advertised scope. Different error behaviour may indicate a separate code path or prompt-only enforcement, but that is a hypothesis signal and not a bypass. Claim the bypass only after retrieving a harmless sentinel you planted outside the allowed boundary.
Example payloads
# 1) Four probes, not two. The comparison is the test.
read_file("./allowed.txt")    known-existing, in scope
read_file("./absent.txt")     known-missing,  in scope
read_file("../sentinel.txt")  known-existing, OUT of scope
read_file("../absent.txt")    known-missing,  OUT of scope

# Differing errors across the boundary is a
# HYPOTHESIS: separate code path, or prompt-only.
# It is not yet a bypass.

# 2) Bypass is proven only when the out-of-scope
#    sentinel YOU planted returns by content.
#    Use an assessment-owned file. Never a real key.

What it is
When a RAG target has input filters blocking specific keywords, submit queries using semantic equivalents that produce near-identical embeddings but avoid the filter. # Filter match: 0 (neither "password" nor "credentials" present)
# Retrieval: returns the same top-k results

# Paired-query confirmation:
#   run the blocked query on an open instance,
#   run the equivalent on the target, then
#   compare returned doc IDs / citations.
